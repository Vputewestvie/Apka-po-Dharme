# Локальный запуск «точно как в продакшене»

**Дата**: 2026-08-29
**Проект**: Дневник духовной практики (`C:\Proekti\Mini apka dlya po dharme`)
**Задача**: поднять приложение локально так же, как оно работает в бою, чтобы вручную проверить все кнопки, но без публикации на сервер.

---

## TL;DR

- Приложение работает: **http://localhost:3001/local.html**
- Режим: `NODE_ENV=production` — dev-обход авторизации выключен, всё идёт через настоящие Telegram init data.
- Бот **@DharmaPractic_bot** поднят и принимает обновления через long polling — публичный HTTPS-адрес не нужен.
- Проверено: сценарий по всем кнопкам — **27/27**, модульные тесты — **27/27**, `tsc --noEmit` — чисто.
- По пути найден и исправлен дефект: **бот не загружал `.env`** и в продакшене не стартовал бы вовсе.

## Что значит «как в продакшене»

| | Обычный dev-запуск | Этот запуск |
|---|---|---|
| Мини-апка | Vite dev-сервер на :5173 | прод-бандл `vite build`, раздаётся самим API |
| Кто отдаёт файлы | Vite | API из `apps/mini-app/dist` |
| `NODE_ENV` | development | **production** |
| Авторизация | `x-user-id` (dev-заголовок) | **настоящие Telegram init data** (HMAC + срок годности) |
| dev-обход | включён | **выключен** |
| Бот | обычно не запускают | запущен, long polling |

Ключевой момент: в production `isDevAuthEnabled()` требует одновременно `NODE_ENV !== "production"` **и** `ALLOW_DEV_AUTH=1`, поэтому заголовок `x-user-id` перестаёт работать. Значит, приложение обязано авторизоваться init data — ровно так, как внутри Telegram.

---

## Как это устроено

### 1. Init data без клиента Telegram

В браузере нет `window.Telegram`, откуда приложение берёт init data. Скрипт `scripts/prepare-local-prod.mjs` формирует их заранее и подписывает **настоящим токеном бота**:

```
secret_key = HMAC-SHA256("WebAppData", botToken)
data_check_string = все поля, отсортированные по ключу, через "\n", без hash
hash = HMAC-SHA256(secret_key, data_check_string)
```

Результат кладётся в `dist/local-telegram.js` — синхронную заглушку, которая выставляет `window.Telegram` до загрузки бандла. Официальный скрипт `telegram-web-app.js` из `local.html` убран, иначе он перезаписал бы заглушку.

API проверяет эти init data обычным боевым путём: подпись, `auth_date` (не из будущего, не старше 24 часов), сравнение `timingSafeEqual`.

### 2. Бандл без dev-переменных

`scripts/prepare-local-prod.mjs` на время сборки убирает `apps/mini-app/.env`.

Причина: там лежит `VITE_DEV_USER_ID`, а `getAuthHeaders()` в `src/api.ts` проверяет его **первым** и при его наличии шлёт `x-user-id`, не доходя до Telegram. В production такой бандл получал бы 401 на каждый запрос.

После сборки скрипт проверяет, что в бандле не осталось строки `x-user-id`, — это контроль того, что сборка действительно прошла по боевому пути.

## Найденный дефект: бот не загружал `.env`

**Симптом**: `npm run start:bot` падал сразу после старта:

```
Error: TELEGRAM_BOT_TOKEN is required
    at readBotConfig (apps/bot/src/config.ts:14:11)
```

**Причина**: загрузчик `.env` жил только внутри `apps/api/src/http.ts`. У бота своего не было, и он читал голый `process.env`. То есть бот запускался бы, только если переменные заранее экспортированы в шелл — в продакшене это означало бы, что **уведомления не работают вообще**.

**Решение**: загрузчик вынесен в `packages/shared/src/load-dot-env.ts` и подключён к обоим приложениям. Сохранена важная семантика: переменные, уже заданные в окружении, файл не перезаписывает — в проде окружение всегда главнее `.env`.

Это тот же класс проблемы, что и с Vite (он не видит `.env` из корня монорепо): в монорепо каждой точке входа нужен свой загрузчик, и расхождение между ними легко пропустить.

## Как запускать

### Быстро
```
start-local-prod.cmd     →  откроет http://localhost:3001/local.html
stop-local.cmd           →  остановит
```

### Вручную
```bash
cd "C:/Proekti/Mini apka dlya po dharme"
unset NODE_OPTIONS && export CODEBUDDY_SAFE_DELETE_ENABLED=0

node scripts/prepare-local-prod.mjs          # сборка + подпись init data
NODE_ENV=production npm run start:api        # API + раздача dist
NODE_ENV=production npm run start:bot        # бот (long polling)
```

`unset NODE_OPTIONS` обязателен: среда WorkBuddy подменяет `rm`/`unlink` и ломает распаковку npm.

## Известные ограничения

1. **Init data действительны 24 часа.** Потом надо перезапустить `prepare-local-prod.mjs` — он выпустит свежую подпись. Если увидите 401 «Invalid Telegram init data signature», причина именно в этом.

2. **Внутри настоящего Telegram пока не открыть.** Telegram требует HTTPS-домен. Сейчас приложение доступно только через `local.html` в обычном браузере. Для боя нужен домен с TLS и `MINI_APP_URL` на него.

3. **Google AI Studio заблокирован.** Ключ валиден, но API disabled в Google Cloud проекте `1013877118446` (`API_KEY_SERVICE_BLOCKED`). Работает через OpenRouter (`deepseek/deepseek-v4-flash`).

4. **Картинок категорий всего три**: `pranayama`, `qigong`, `reading`. Медитация использует `pranayama.jpg` — файла `meditation.jpg` в проекте нет.

5. **Rate limiting не реализован.** На боевом deployments это стоит добавить.
